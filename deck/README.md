# Vault (PocketRAG) — pitch deck

`Vault_PocketRAG_Deck.pptx`, 13 slides, 16:9. Generated by `build_deck.py`.

```bash
python build_deck.py        # -> Vault_PocketRAG_Deck.pptx
```

Only `python-pptx` is needed. Editing the deck means editing the script and
re-running it, not editing the .pptx — a hand edit is lost on the next build.

## What this deck argues

The **real system**, not the bench prototype. Same relationship the
`vault_video/` explainer has to `vault_rag_test/`: it describes the target
architecture — NPU delegate, sqlite-vec, SQLCipher, Office Kit bridge,
on-device generation — because that is what gets built.

The prototype appears exactly once, on **slide 09**, where it is the measured
floor under the claims rather than the subject. That slide also carries the
divergence table from `vault_video/README.md`, so the gap between the video's
architecture and what runs today is stated on a slide rather than discovered
in Q&A.

## Claims and where they come from

Everything numeric traces to `vault_rag_test/BUILD_NOTES.md`:

| Claim | Source |
|---|---|
| 233 ms query embedding, 256 tokens | measured, realme RMX3660 / SD695 / Android 14 |
| 567 ms model load | same |
| 12× XNNPACK (2,782 ms → 224 ms) | same |
| Zero permissions in release APK | `aapt2 dump permissions` + on-device `dumpsys` |
| 13/13 unit tests | `flutter test` |

`~800 tokens` and `1 GB / ~4 KB` are the design budget, not measurements, and
are labelled as approximate on the slides. The "1 part in 250,000" ratio on
the hero and on slide 06 is derived from those two — keep them in step if
either changes.

**Do not upgrade the NPU claim.** Slide 09 says explicitly that the NPU path
is unproven; on a Snapdragon 695 it never materialised. If the hackathon
hardware exposes a working vendor delegate, measure it before the number
moves.

## Design

Palette is `vault_video/src/theme.ts` verbatim — which is also the
`ui-ux-pro-max` "VPN & Privacy Tool" entry, so the deck and the video are the
same system by construction. Green means on-device, red means it left the
device, and nothing else in the palette is saturated.

Grid is the editorial one from `ground-zero-mesh/deck/build_deck.py`: eyebrow →
headline → standfirst → content → hairline + folio. Type is Aptos, which ships
with Office, rather than the video's Inter, so the file renders identically on
a machine that has never seen this repo.

## Checking a change

There is no CI for layout, so re-render after editing. With PowerPoint
installed:

```bash
powershell -Command "$app = New-Object -ComObject PowerPoint.Application; $p = $app.Presentations.Open('<abs path>\Vault_PocketRAG_Deck.pptx', $true, $false, $false); $p.Export('<abs path>\png', 'PNG', 1600, 900); $p.Close(); $app.Quit()"
```

Then look at the PNGs. Text boxes do not clip in python-pptx — overflowing
copy silently overlaps whatever is beneath it, which is how every layout bug
in this deck has shown up so far.
